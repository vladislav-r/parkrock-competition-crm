# ParkRock Hub

API-first MVP для проведения скалолазного фестиваля. В проекте два интерфейса:

- публичные онлайн-результаты: `http://localhost:3000`;
- рабочее место администратора: `http://localhost:3000/admin`.

Стек: Next.js + TypeScript, FastAPI, PostgreSQL. Redis не используется.

## Запуск

При запущенном Docker Desktop:

```powershell
.\scripts\start-dev.ps1
```

Обычный запуск применяет миграции базы, но не создает и не изменяет демонстрационные записи. Явное заполнение демоданными доступно только отдельной командой:

```powershell
.\scripts\seed-demo.ps1 -ConfirmDemoData
```

API и его документация доступны по адресам `http://localhost:8001` и `http://localhost:8001/docs`.
Локальная панель мониторинга Grafana запускается той же командой и доступна по адресу `http://127.0.0.1:3001/d/parkrock-performance`; вход не требуется. Локальные метрики хранятся не более 6 часов и ограничены 64 МБ.

## Production на VPS

Для production подготовлены отдельные контейнеры frontend, backend и PostgreSQL, а также Caddy с автоматическим HTTPS. Конфигурация находится в `docker-compose.prod.yml`, шаблон секретов — в `.env.production.example`, пошаговое развёртывание и перенос базы — в `DEPLOY_VPS.md`.

Минимальный мониторинг production выполняют Prometheus и готовая панель Grafana: они показывают частоту, статусы и длительность запросов API, а также CPU и память backend. Данные хранятся не более 3 дней и ограничены 256 МБ. Grafana доступна по адресу `https://DOMAIN/monitoring/` с отдельным логином и паролем из `.env.production`.

Тестовый вход администратора:

- почта: `admin@parkrock.test`;
- пароль: `demo1234`.

## Реализовано

- публичные таблицы результатов по возрастным категориям;
- главная страница фестиваля и отдельные URL для каждой возрастной категории;
- полный список заявленных участников в категории с пустыми результатами до первого прохождения;
- выделение десяти финалистов и всех участников с равным пограничным результатом;
- публичная карточка участника без персональных служебных данных;
- автообновление опубликованных результатов каждые три секунды;
- админский список сетов и участников, поиск и карточка участника;
- отметка пройденных трасс с автоматическим расчетом очков;
- подтверждение, блокировка и повторное открытие сета;
- сохранение последнего подтвержденного снимка при исправлении результатов;
- импорт коллективных и индивидуальных заявок из CSV/XLSX с предварительной проверкой строк;
- ручное добавление участника с проверкой дубликата и вместимости;
- предварительное распределение всех участников по сетам;
- глобальный поиск по стартовому номеру и подтверждение фактического входа;
- отдельные счетчики назначенных и пришедших участников по каждому сету;
- лимит сета 50 человек;
- автоматическая выдача уникального стартового номера.

## Формат импорта

Обязательные колонки: `Фамилия`, `Имя`, `Отчество`, `Дата рождения`, `Пол`, `Разряд`, `Клуб`, `Сет`.
Дополнительные колонки: `Представитель`, `Мерч`. Даты принимаются в формате `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`.

В колонке `Сет` указывается название назначаемого сета, например `Сет 1`. Также принимается английское название колонки `Set`. Один файл может содержать участников разных сетов. Переполнение не выполняется автоматически и требует отдельного подтверждения администратора.

Уникальность стартового номера защищена ограничением PostgreSQL `UNIQUE (event_id, start_number)` и транзакционной блокировкой при импорте.
Перед импортом система показывает предварительную проверку всех строк и выделяет ошибочные ячейки. Дубликаты определяются по сочетанию `Фамилия + Имя + Отчество + Дата рождения`; при наличии дубликатов можно загрузить только корректные строки.

## Безопасность базы

Структура базы изменяется миграциями Alembic. `scripts\start-dev.ps1` автоматически применяет только недостающие миграции.

Создать полную резервную копию вне Docker volume:

```powershell
.\scripts\backup-db.ps1
```

Проверить восстановление в отдельной базе `climbhub_restore_test`:

```powershell
.\scripts\restore-db.ps1 -BackupPath .\backups\climbhub-YYYYMMDD-HHMMSS.dump -ConfirmRestore
```

Восстановление в рабочую базу дополнительно заблокировано. Никогда не выполняйте `docker compose down -v`, эта команда удаляет volume PostgreSQL.

## Проверки

Backend-тесты работают только с отдельной базой `climbhub_test` и отказываются запускаться на рабочей базе:

```powershell
.\scripts\test-backend.ps1
```

Проверка production-сборки интерфейса:

```powershell
Set-Location frontend
npm run build
```
