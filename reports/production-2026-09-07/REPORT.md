# Проверка боевой ParkRock CRM — 07.09.2026

Адрес: https://live.parkrock27.ru. Проверены реальные API и интерфейс. Метрики получены из Prometheus, логи — из Loki через прокси источников Grafana. SSH, развёртывание и изменение кода приложения не выполнялись.

## Вывод

Основная репетиция подготовки, квалификации, финала, завершения и возврата в подготовку прошла. Обнаружен дефект идемпотентности запуска этапов. Полную безотказность и готовность к пиковой нагрузке эта проверка не подтверждает.

## Подтверждённая проблема

**P1: повтор успешно выполненного запуска этапа возвращает 409 вместо результата исходной операции.**

Воспроизведено на `POST /api/v1/admin/final/qualification/start` и `POST /api/v1/admin/final/start`: первый запрос возвращает 200, повтор с теми же телом и `X-Operation-Id` — 409 («Квалификация уже началась» / «Финал уже запущен»). Повторного перехода и потери данных не произошло. Однако после потери ответа клиент не может отличить успешную операцию от отказа штатным повтором.

В локальном `backend/app/routers/admin_final.py` проверка текущего этапа выполняется раньше получения сохранённого результата операции. Нужен отдельный фикс с регрессией повторов переходов, включая завершение и откаты. В этой задаче фикс не выполнялся.

## Что проверено

- HTTPS, health API, публичные страницы и OpenAPI доступны.
- Все шесть предоставленных аккаунтов успешно авторизовались, роли и назначения судей соответствуют назначению.
- Матрица чтения для шести аккаунтов: мероприятие, участники, пользователи, резервные копии, финал, рабочее место судьи. Запреты 403/409 соответствовали роли и этапу. Без авторизации административные данные возвращали 401.
- Ресепшен и судья не смогли создать сет; ресепшен не смог изменить квалификационные результаты.
- Создан один тестовый сет вместимостью два человека и два индивидуальных участника: «Тестовый Альфа», «Тестовый Бета». Повтор создания с прежним идентификатором операции не создавал дублей; отдельное создание дубликата и превышение вместимости отклонены.
- Прибытие/оплата, повтор операции ресепшена, отказ устаревшему изменению, запрет переноса уже прибывшего участника.
- Запрет записи квалификационных результатов до начала квалификации и до подтверждения прибытия.
- Квалификационные результаты 200 и 100 баллов, подтверждение категорий, блокировка преждевременного запуска финала.
- XLSX квалификации и финала возвращены сервером и разобраны библиотекой openpyxl; тестовые имена присутствуют. Размеры проверенных файлов — 7048 и 7053 байта. Проверка непосредственно в Microsoft Excel не выполнялась.
- После старта финала добавление участника и изменение квалификационных результатов отклонены.
- Два судьи параллельно записали результаты одного финалиста на разных трассах — оба запроса 200. Повтор исходной операции — 200; попытка новой записи судьёй поверх сохранённой — 409.
- Расчёт финала: 24,9 + 24,8 = 49,7; второй участник — 24,9. Итоговые места 1 и 2, порядок выхода сохранён отдельно. Эти значения совпали в административном API и публичной таблице.
- В браузере: вход судьи, инструкция роли, выбор участника, попытка/зона/топ, отмена последнего действия, двойное подтверждение и сообщение «Сохранено на сервере».
- Судейский черновик с двумя действиями сохранился после перезагрузки страницы и повторного выбора участника при доступной сети.
- Завершение запрещено до подтверждения финальных категорий; после подтверждения событие перешло в completed.
- Отмена завершения, возврат из финала в квалификацию и из квалификации в подготовку прошли. Для возвращения исходных назначений трасс потребовался дополнительный запуск финала с очищенными тестовыми попытками: штатная защита не разрешает менять трассы при существующих результатах.
- Публичная страница автоматически обновилась после удаления тестовых данных. На проверке viewport 390 px ширина документа не превышала ширину окна. В журнале браузера проверенной публичной вкладки ошибок/предупреждений не было. Это не полноценная приёмка на физическом телефоне или слабом ноутбуке.
- CORS preflight для отправки заявки с `https://fest.parkrock27.ru` — 200 с соответствующим разрешённым Origin. Лендинг открывался однократно; файлы заявок не отправлялись и не импортировались.

## Ограниченная проверка нагрузки

Только публичный API CRM, без нагрузки на лендинг. 90 запросов к `/api/v1/public/results`, целевой темп 2 запроса/с, длительность 44,7 с. Все ответы 200. Клиентские задержки: медиана 194,4 мс, p95 494,7 мс, максимум 2370,3 мс. Серверный p95 по метрикам всех API за пять минут после проверки — около 45,4 мс; эти измерения имеют разные окна и границы измерения.

Во время более раннего подключения тестового клиента был единичный TCP ConnectTimeout; повторное подключение прошло. Он не воспроизвёлся в серии из 90 запросов, причина не установлена. Его нельзя уверенно приписать приложению или считать проверенным сценарием офлайн-очереди.

## Не аттестовано

- Настоящее отключение сети в браузере судьи до/во время отправки, очередь после 409 и перезапуск устройства без сети. Доступный браузерный интерфейс не предоставляет управление сетью; отключение общей сети компьютера не выполнялось.
- Длительная нагрузка с ожидаемым числом участников и зрителей, отказ процесса/БД и восстановление сервиса.
- Реальный слабый ноутбук и несколько физических устройств.
- Вынос копий на независимый сервер/хранилище, заполнение диска, алерты и доставка уведомлений. В доступных источниках видны backend и PostgreSQL, но не весь хост.
- Сквозная отправка файла с лендинга в рамках этой репетиции: выполнен только CORS и просмотр, с учётом просьбы минимизировать заявки.
