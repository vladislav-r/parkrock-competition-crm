# Инструкции для работы с ParkRock Hub

## Общение

- Всегда отвечай на русском языке.
- Пиши кратко и по существу, не пересказывай запрос и ТЗ.
- Промежуточные сообщения ограничивай одним-двумя предложениями.
- Финальный ответ обычно ограничивай результатом, проверкой и ссылкой на интерфейс.
- Если пользователь просит только обсудить или объяснить, не изменяй код.

## Экономия контекста

- В начале задачи прочитай `PROJECT_STATE.md`, затем только файлы, непосредственно относящиеся к запросу.
- Не сканируй весь репозиторий и не перечитывай все ТЗ без явной необходимости.
- Для поиска используй узкие запросы `rg` по известным каталогам и символам.
- Не открывай повторно уже прочитанный неизмененный файл в рамках одной задачи.
- Не выводи большие файлы целиком, если достаточно нужного диапазона или поиска.
- Не повторяй в ответе сведения, уже зафиксированные в `PROJECT_STATE.md`.
- Актуальное ТЗ перечитывай только по запросу пользователя или когда задача зависит от конкретного требования.

## Реализация и проверка

- Делай минимальные изменения в существующей архитектуре.
- Запускай минимальный достаточный набор проверок для измененной области.
- Полную сборку запускай для общих изменений, перед завершением крупной функции или когда локальная проверка недостаточна.
- Скриншоты и браузерную проверку используй для изменений интерфейса; для backend-only изменений ограничивайся API и тестами.
- Не создавай временные файлы и данные без необходимости. Всегда удаляй их после проверки.
- Не описывай пользователю внутренние команды и длинные технические журналы, если он их не запросил.

## Данные и область доступа

- Соблюдай правила безопасности из `PROJECT_STATE.md`.
- Никогда не выполняй `docker compose down -v`.
- Не очищай и не пересоздавай базу без прямого подтверждения пользователя.
- Не изменяй другие папки рабочего стола.
- В Obsidian работай только с `C:\Users\admin\Documents\Obsidian Vault\ТЗ ParkRockHUB`.

## Поддержание контекста

- Обновляй `PROJECT_STATE.md` только при существенном изменении архитектуры, предметных правил, способов запуска или завершении крупного блока.
- Не записывай туда временные счетчики, идентификаторы, тестовые данные и подробный журнал изменений.
- Текущие незавершенные задачи храни в `TODO.md`, не дублируй их подробно в других файлах.
